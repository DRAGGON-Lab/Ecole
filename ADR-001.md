# ADR-001: Separate genomic dataset production from model training

**Status:** Accepted for initial implementation.

## Context

ATCG-FM combined a standalone benchmark-generation notebook with model/evaluation notebooks. Data pipeline changes should be reviewed and versioned independently of PyTorch experiments.

## Decision

Use Ecole as a Python-only dataset producer that releases named immutable datasets and schema-2 manifests. ATCG-FM consumes FASTA files and metadata without importing Ecole as a runtime dependency.

## Alternatives

- **Keep notebook in ATCG-FM:** lowest immediate effort, but tight coupling, difficult data provenance.
- **Share a monorepo package:** reusable code but the dataset's release cycle remains tied to model development.
- **Independent Ecole repository (chosen):** clean ownership and review boundaries at the cost of a versioned file/manifest integration.

## Consequences

Maintain the fixed five-split file layout and manifest fingerprint contract. Release builders must be tested independently. New storage providers and derived token representations are added behind additive versioned interfaces.

## Risks and mitigations

A copied reference implementation can drift from previous output: pin historical source IDs, compare manifests and quotas, use immutable release names and require documented differences. ANI groups currently come from upstream metadata and require independent taxonomic verification.

## Revisit

Reconsider the artifact boundary if multiple unrelated model consumers demand a shared standardized dataset format or a formal cross-project schema library.
